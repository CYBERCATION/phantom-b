Before you start

PHANTOM-B deliberately covers only the LLM-specific risks. Run it alongside STRIDE or your normal SDL review, not instead of it. It slots into the Four Question Framework:

1. What are we working on?Describe the system and where the LLM sits.
2. What can go wrong?Walk the eight letters below.
3. What are we going to do about it?Record a mitigation and owner per finding.
4. Did we do a good job?Export, review and revisit when the system changes.

Everything you type stays in this browser. Nothing is sent anywhere. Don't paste secrets or classified detail; use the export to store results somewhere approved.

Also consider

Questions that sit just outside the eight letters but come up in almost every LLM review.

Where does the prompt data go?

  • Is the model local, in our cloud tenant, or a third-party service?
  • Are prompts and outputs logged, retained, or used for future training?
  • Could data from one session or customer influence another?
  • What does the provider contract say, and what's the supply-chain risk?

Sandbox it like untrusted code

  • Fix the input format and validate it before it reaches the model
  • Require a strict output schema and reject anything that doesn't match
  • Limit what the output can reach: no direct path to code execution
  • Assume guardrails will sometimes fail, and cap the blast radius
